# Что заявляет oh-my-pi (omp) как преимущества

Разбор по README и `docs/` клона `can1357/oh-my-pi` (Stencil Labs, MIT, форк Pi от @mariozechner). Заявка в шапке: «60+ провайдеров, 31 встроенный инструмент, 14 LSP-операций, 28 DAP-операций, ~80 тыс. строк Rust-ядра».

## Их список (сжато, по разделам README)

1. **«Каждый инструмент выжат до предела».** Правки, которые проходят с первой попытки (замеры: Grok Code Fast 6.7% → 68.3%, Gemini 3 Flash +5 п.п. к `str_replace`, Grok 4 Fast −61% токенов вывода, MiniMax 2.1×). Чтение с суммаризацией вместо вываливания файла, быстрый grep, LSP в каждой записи, промпты, подогнанные под каждую модель.
2. **Persistent eval-ядра** (Python + Bun) с обратным вызовом инструментов агента через loopback-мост: из Python можно звать `read`, из JavaScript — строить график, не выходя из ячейки.
3. **LSP подключён к каждой записи**: переименование идёт через `workspace/willRenameFiles`, обновляются ре-экспорты и barrel-файлы.
4. **Настоящий отладчик**: DAP-сессии — lldb, dlv, debugpy; точки останова, шаги, потоки, стек, переменные.
5. **Time-traveling stream rules (TTSR)**: правило спит, пока модель не пойдёт не туда; regex обрывает стрим на полу-токене, правило впрыскивается системным напоминанием, ретрай с той же точки. Инъекции переживают компрессию — «коррекция без контекстного налога на каждом ходу».
6. **Субагенты первого класса**: `task` разветвляет работу по изолированным worktree, воркеры возвращают типизированный результат по схеме, родитель читает его напрямую (без разбора прозы); `Alt+A` открывает Agent Hub — россыпь субагентов с живым транскриптом, отправкой steer-сообщений, оживлением запаркованных и убийством зависших воркеров.
7. **Advisor**: вторая модель с собственным контекстом читает каждый ход главного агента и впрыскивает замечания — тихое замечание, тревога, жёсткий блокер.
8. **`/collab`**: живая сессия выкладывается на релей, отдаётся ссылка и QR; можно подключиться из другого терминала или браузера, в режиме чтения или с правом рулить.
9. **`web_search` цепочкой из 23 провайдеров**, и найденные URL сразу уходят в `read`: arxiv-PDF, GitHub, Stack Overflow возвращаются структурным markdown с анкорами.
10. **«Нативность без исключений»**: ripgrep, glob, find слинкованы внутрь процесса (без fork/exec), свой bash (brush) с 58 встроенными утилитами, один бинарь на macOS/Linux/Windows.
11. **`/review` с приоритетами и вердиктом**: P0–P3 с оценкой уверенности, отдельные субагенты-ревьюеры параллельно по веткам/коммитам; `/annotate` — пины заметок к строкам диффа.
12. **Hashline**: правка по якорям-хешам вместо перепечатывания строк — конец битвам с пробелами и циклам «строка не найдена»; устаревший файл отвергается до порчи содержимого (−61% токенов вывода на Grok 4 Fast).
13. **GitHub как файловая система**: без `gh_pr_view`-обёрток — PR это путь, `read` уже умеет пути.
14. **Память, которую агент ведёт сам**: `retain` / `learn` / `recall`, сжатие сессии в модель следующего запуска, бэкенды `local`, Hindsight, Mnemopi; по умолчанию скоуп — проект.
15. **ACP: агент, управляемый редактором** (Zed и др.).
16. **Наследует конфиги других инструментов**: Cursor MDC, Cline `.clinerules`, Codex `AGENTS.md`, Copilot — без конвертеров.
17. **`omp commit`**: атомарные разбиения по зависимостям, сообщения с валидацией, lock-файлы из анализа исключены.
18. **16 внутренних схем** (`pr://`, `issue://`, `agent://`, `skill://`, `ssh://`), резолвятся внутри всех FS-инструментов.
19. **Разрешение конфликтов через URL**: `conflict://1` + `@theirs`/`@ours`/`@base`.
20. **Preview-then-accept** для структурных правок (`ast_edit` + `xd://resolve` → карточка Accept).
21. **Настоящий браузер** (Puppeteer/CDP, stealth по умолчанию, релей к своим вкладкам Chrome) и **управление рабочим столом** (окна, скриншоты, нативный ввод, AX-дерево, буфер обмена).
22. **Интерфейсные документы, которых нам не хватает**: `slash-command-internals.md`, `keybindings.md` (перемаппинг в `~/.omp/agent/keybindings.yml`), `theme.md`, `skills.md`, `hooks.md` + `extensions.md`.

## Что из этого имеет смысл для znth

Оценка под наш скоуп (Python-ядро Hermes, TUI на Ink, UX как в Claude Code, параллельно режем лишнее).

**Стоит взять идеей (не кодом):**

- **Hashline — правка по якорям-хешам.** Прямая экономия токенов вывода и конец циклам «строка не найдена». У нас правки идут сопоставлением текста (`patch`/`old_string`), устаревший файл ловится, но перепечатывание строк никуда не уходит.
- **TTSR — правила на потоке.** Это ровно тот механизм, который нужен твоему требованию «хуки скиллов через `/`» и вообще дисциплине поведения: правило впрыскивается, когда модель пошла не туда, и переживает компрессию. У Hermes есть только постфактум-критика (`agent/background_review.py`), впрыска на потоке нет.
- **Advisor — вторая модель, читающая каждый ход.** В Hermes вспомогательные модели есть (`agent/auxiliary_*`), но они работают на компрессию, заголовки и vision, а не как наблюдатель.
- **Agent Hub — панель субагентов.** У нас `delegate_task` есть, а живого мониторинга с steer/kill для субагентов — нет (kanban покрывает другое).
- **`keybindings.yml` — перемаппинг клавиш файлом.** Прямо в цель «UX как в Claude Code»: свои привычные биндинги без правки кода.
- **LSP и DAP как инструменты агента.** У Hermes есть LSP-каталог и скиллы по отладке (`python-debugpy`, `node-inspect-debugger`), но стоит сверить охват с их 14 LSP + 28 DAP операциями.

**Не наше (их стек, не переносим):**

- Rust-ядро на ~80 тыс. строк, in-process coreutils, brush-bash, нативность без fork/exec, Windows-бинарь одним файлом.
- 60+ провайдеров моделей и цепочка из 23 провайдеров поиска — у нас правило: только то, что локально и селфхостед.
- `/collab` через релей, marketplace, плагин-инфраструктура на Bun, handoff-пайплайны.

**Проверить отдельно:**

- Persistent eval-ядра с обратным вызовом инструментов: в Hermes есть `execute_code` и `code_kernel`, надо понять, даёт ли их ядро обратный вызов в инструменты агента, и стоит ли это делать.
- `omp commit` (атомарные коммиты с разбором зависимостей) — у нас есть `git`-инструменты, но такой автоматизации нет.
