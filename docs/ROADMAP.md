# Роадмап znth-agent

Черновик v0.1. Собран так, чтобы каждая фаза запускалась в goal-режиме автономно: у фазы есть цель, шаги, критерий готовности и проверка, которая доказывает результат, а не описывает его.

## Что строим

Свой ИИ-агент: ядро Hermes Agent (Python), из которого вырезано всё лишнее, и UX, перенесённый из openclaude. Репозиторий ведётся как самостоятельный проект с чистой историей, апстрим подтягивается отдельным локальным клоном.

Известные числа базлайна (`ae3f9f9`, 2026-10-13): 18 326 файлов в дереве, крупные блоки — `tests/` 66 МБ, `apps/` 53 МБ, `website/` 29 МБ, `hermes_cli/` 276 тыс. строк, `agent/` 137 тыс. строк, `tools/` 125 тыс. строк, `ui-tui/` 106 тыс. строк.

## Инварианты (не нарушать при резке)

1. **Промпт-кэш священен.** Ничего не меняет прошлый контекст и системный промпт посреди разговора; исключение одно — компрессия контекста.
2. **Ядро — узкая талия.** Каждый инструмент уходит в модель на каждом вызове: расширение живёт скиллами, CLI-командами и плагинами, а не новыми инструментами ядра.
3. **Резка — это удаление, а не переписывание.** Где можно удалить файл целиком — удаляем; где понятие вшито в дюжину файлов — ставим заглушку-резолвер.
4. **Доказательство вместо заявления.** После каждого прохода: строгий импорт, сборка набора инструментов, смоук-прогон.

## Фазы

### P0. Базлайн и репозиторий — СДЕЛАНО
- Снимок актуального апстрима `NousResearch/hermes-agent` @ `ae3f9f9`.
- Публичный репо `lowcoware/znth-agent` с чистой историей (один коммит), апстрим-клон локально для мержей и откатов.
- Наши документы: `docs/ROADMAP.md`, `docs/PLAN.md`, `docs/QUESTIONS.md`.
- **Готово, когда:** репо публикуется, дерево совпадает с апстримом (расхождение только наши файлы), локально поднимается `git clone ~/hermes-agent-upstream`.

### P1. Решения и заморозка плана — СЛЕДУЮЩАЯ
- Ответы на `docs/QUESTIONS.md` (блоки A-F).
- Согласование областей резки по номерам из `docs/PLAN.md`: режем только то, на что дан явный ответ.
- Фиксация в `docs/DECISIONS.md`: что оставляем, что режем, почему, чем оживает оставленный механизм.
- **Готово, когда:** по каждой области плана есть вердикт (резать / оставить / заглушить), и ни один ответ не противоречит другому.

### P2. Резка: проход за проходом
Порядок — от крупного и безопасного к ядру:
1. Ассеты и тексты апстрима: `contributors/`, README-локали, лишние `SECURITY*/CONTRIBUTING*` (или замена своими).
2. `website/`, `evals/`, `acp_adapter/`, `optional-skills/`, `plugin-catalog/`, `optional-mcps/`, `locales/` — по решению владельца.
3. Поверхности: `apps/*`, `web/` + `tui_gateway/` + `apps/shared` (набором, не по одному каталогу).
4. Платформы: из 21 оставляем согласованные.
5. Провайдеры моделей: из 41 профиля — согласованные.
6. Плагины по областям: browser, computer_use, image_gen, video_gen, memory, context_engine, kanban, google_meet, teams_pipeline, hermes-achievements, dashboard_auth, disk-cleanup, security-guidance, web, cron_providers.
7. Инструменты: файлы `tools/<имя>_tool*.py` **и** имена в `toolsets.py` / `_HERMES_CORE_TOOLS` — двумя поверхностями, не одной.
8. Тесты: до чистого `pytest --collect-only` + тесты оставшихся областей.
- **Правила прохода:** одна область = один коммит с числами; перед удалением каталога читать его манифест (в одном каталоге может жить несколько профилей/записей); после прохода — строгий импорт и починка хвостов в том же коммите.
- **Готово, когда:** согласованные области вырезаны, строгий импорт зелёный, в отчёте названо, что проверено и что нет.

### P3. UX как в Claude Code (донор — openclaude)
Владелец хочет поведение Claude Code, а не текущего Hermes TUI. Берём визуальный язык целиком + компоненты.
- Слой 1: токены и тема (цвета, плотность, отступы, глифы) в `ui-tui`.
- Слой 2: компоненты — статуслайн, строки тул-вызовов, диалоги апрувов.
- Слой 3: поведение интерфейса по образцу Claude Code; палитра команд и режимы (vim, голос) — не первая очередь.
- **Готово, когда:** TUI запускается, рендерит разговор и тул-вызовы в стиле Claude Code, это видно на записи, а не только в коде; смена темы не меняет системный промпт (кэш-инвариант).

### P3b. Совместимость с Claude Code
Два требования владельца:
- **Хуки скиллов через `/`** — слэш-команды для скиллов.
- **Хуки из Claude Code** — поддержка хуковой модели Claude Code (события и, по решению, конфиг из `.claude/settings.json`).
- **Готово, когда:** слэш-хук скилла вызывается из TUI и из мессенджера; хук Claude Code срабатывает на живом прогоне, а не «зарегистрирован в коде».

### P3c. Чистый конфиг и мастер настройки
Требование приёмки владельца: настроить в настройках всё нужное, не видя вереницы ненужных опций.
- Ревизия `hermes_cli/setup*.py`, `config_defaults.py`, `tools_config.py`: из мастера и чеклистов убирается всё, что относится к вырезанным подсистемам.
- **Готово, когда:** мастер настройки с нуля проходится и не встречается ни одного пункта про вырезанное; конфиг содержит только живые ключи.

### P4. Идентичность: hermes → znth
- Команда CLI, имя пакета, `HERMES_HOME`/`~/.hermes`, переменные `HERMES_*`, тексты и промпты — по ответам 33-37.
- Миграция существующего инстанса (если HOME меняется): перенос конфига, памяти, сессий.
- **Готово, когда:** `znth --help` работает на чистой машине, старый инстанс не сломан, в дереве не осталось живых `hermes`-путей, кроме совместимости.

### P5. Своя библиотека скиллов и поведение
- Встроенные скиллы доводятся до минимума, поверх кладётся библиотека владельца (impulse) как каталог встроенных скиллов, чтобы сидировалась на любой установке.
- Правило разбора дублей: сперва влить полезное из встроенного в свою версию, затем удалить встроенный отдельным проходом.
- **Готово, когда:** на чистой машине профиль получает нужные скиллы автоматически, категории не рассыпаются, дублей нет.

### P6. Установка, обновление, CI
- `scripts/install.sh` переводится на свой репозиторий; `hermes update` — на свой origin.
- Минимальный CI: линт, строгий импорт, смоук, тесты оставшегося скоупа.
- **Готово, когда:** установка одной командой на чистую машину проходит и агент отвечает.

### P7. Приёмка первой версии
- Критерии — ответ 42. Базовый набор: агент запускается, отвечает в Telegram, работает в CLI/TUI, число инструментов и скиллов названо, строгий импорт зелёный, смоук проходит, размер дерева и число файлов названы против базлайна.
- **Готово, когда:** критерии проверены на живом артефакте, отчёт с числами «было/стало» приложен.

## Риски

- **Ленивые импорты.** Дерево собирается после удаления и падает на вызове, которого никто не делает. Лечится строгим импортом после каждого прохода.
- **Единица удаления не каталог.** В одном каталоге живут несколько профилей платформы/провайдера; удаление контейнера уносит соседа.
- **Набор инструментов больше статического списка.** Часть наборов регистрируют сами инструменты при импорте; числа брать из разрешённого набора.
- **Вес тестов и ассетов** — 66 + 53 + 29 МБ. Резка этих блоков даёт самый заметный эффект на размер репозитория, но почти ничего — на скорость работы агента.
- **Расхождение с апстримом растёт** с каждым проходом. Мержи апстрима — только через локальный клон, отдельными проходами.
