# Решения по znth-agent

Вердикты по областям из `docs/PLAN.md`. Молчание по номеру = не режем. Ответы владельца записаны его словами там, где формулировка важна.

## Главное правило резки

**Режется всё, что требует чужого аккаунта, чужого API-ключа или платной подписки вендора. Локальное и селфхостедное того же назначения остаётся целиком.**

Правило проверяемо и применяется к провайдерам поиска, браузинга, памяти и моделей — разбор «случай за случаем» не нужен: если для работы нужен ключ или чужой сервис — режем; если работает на своей машине или своём сервере — оставляем.

## Модели

Остаются четыре: **opencode-go**, **opencode-zen**, **gemini native**, **openai-custom**.

- `opencode-go` и `opencode-zen` объявлены одним каталогом `plugins/model-providers/opencode-zen/` (два профиля в одном `__init__.py`: `name="opencode-zen"` и `name="opencode-go"`) — **резать по объявлению, а не по каталогу**, иначе уносим соседа.
- **Новая возможность, которой в апстриме нет:** gemini native должен принимать любой API-адрес при авторизации по ключу. Сейчас вайр выбирается по базовому URL (`is_native_gemini_base_url()` возвращает True только для хостов `generativelanguage.googleapis.com` / Vertex Express), всё остальное уходит в chat-completions. Нужно: нативный Gemini-вайр + произвольный `base_url` с ключом. Правка на несколько строк, годная в апстрим.
- Остальные ~37 профилей режем (anthropic, openai-codex, copilot, vertex, xai, zai, ollama-cloud, bedrock, azure-foundry, alibaba, minimax, qwen-oauth, router и т.д.).

## Поиск и браузинг

Правило владельца: «селфхостед и локал решения по поиску и браузингу оставить полностью».

**Провайдеры поиска** (`plugins/web/`):

- Остаются: `ddgs` (без ключа), `searxng` (свой сервер по `SEARXNG_URL`, localhost), `keyless_mcp.py` (keyless-путь через MCP).
- Режутся: `brave_free`, `exa`, `firecrawl`, `keenable`, `parallel`, `perplexity`, `tavily`, `xai` — всем нужен чужой ключ либо вендорный шлюз.
- Уточнить на проходе: `openai_native` (отдельного ключа в профиле не требует — работает через уже настроенного провайдера).

**Браузер:**

- Остаются локальные движки: Lightpanda, Camofox, CDP, локальный `browser-use` CLI, реальный профиль браузера.
- Режутся облачные провайдеры: `browser_use` (managed), `browserbase`, `firecrawl`.
- **Осторожно:** `tools/browser_tool_cloud.py` держит не только облачный резолвер, но и общие помощники конфигурации браузера (headed-режим, выбор движка, политика приватных URL). Файл не удаляем — заглушаем резолвер `_get_cloud_provider()`.

## Идентичность и брендинг

**Полный ребрендинг.** Команда CLI, `HERMES_HOME` / `~/.hermes`, имя пакета, переменные `HERMES_*`, все тексты и промпты переезжают на znth / ZNTH.

Риск, который надо закрыть до этого шага: этот инстанс (в котором мы сейчас работаем) живёт на `HERMES_HOME=~/.hermes` с запущенным гейтвеем. Переименование HOME и переменных без миграции ломает работающего агента. Поэтому фаза идёт отдельным проходом со скриптом миграции (конфиг, `.env`, память, сессии, авторизации) и путём отката. Порядок внутри фазы: сначала внутренние имена и тексты, затем команда CLI, затем HOME с миграцией, затем переменные окружения.

## Скиллы, локали

- Встроенные скиллы (58 в 12 категориях): **резать до минимума**, сверху кладётся своя библиотека (impulse) в каталог встроенных скиллов форка — тогда она сидируется на любой установке.
- `optional-skills/` (860 файлов, 155 `SKILL.md`, 15 МБ, 22 категории): **резать целиком**.
- `locales/` (35 файлов, 87 тыс. строк, 15 языков): **оставить только `ru` и `en`** вместе с их `.tui`-вариантами, остальные 13 языков режем.

## Установка и CI

- Свой `install.sh` на своём репозитории плюс свой путь обновления вместо `hermes update`.
- **Полный CI с тестами** (не минимальный: линт, строгий импорт, смоук, тесты оставшегося скоупа).

## UX из openclaude: что берём

**Визуальный язык целиком + компоненты.** Тема, цвета, плотность, глифы; статуслайн, строки тул-вызовов, диалоги апрувов. Палитра команд и поведение клавиш (vim, голос) — не в первой очереди.

## Приёмка первой версии (формулировка владельца)

«Нормально должен работать агент, и можно будет уже в настройках себе настроить всё, что надо, не видя вот этой вереницы всякой ненужной хрени».

Из этого следует отдельная работа, а не только резка: **чистый конфиг и чистый мастер настройки**. Настройки должны показывать только то, что у znth реально есть, и не вываливать опции вырезанных подсистем. Проверка приёмки: пройти мастер настройки с нуля и не встретить ни одного пункта про вырезанное.

## UX: цель — как в Claude Code

Формулировка владельца: «Весь текущий UX бесит, я привык к UX Claude Code, нужно чтобы всё работало как в Claude Code». Плюс два конкретных требования:

1. **Хуки скиллов через `/`** — слэш-команды для скиллов.
2. **Поддержка хуков из Claude Code** — совместимость с хуковой моделью Claude Code.

Визуальный язык и компоненты берём из openclaude (он и есть клон Claude Code по UX), поведение — тоже по образцу Claude Code, а не по образцу текущего Hermes TUI.
