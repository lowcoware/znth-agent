# Проход 3b: каналы, имена и состояние CI

## Что срезано в каналах

Владелец решил: **только Telegram**. Срезаны 20 каналов-плагинов (+ `teams_pipeline`), затем
корневые адаптеры (Signal, Weixin, BlueBubbles, QQ Bot, Yuanbao, WhatsApp Cloud, MSGraph),
их подкоманды CLI, WhatsApp-онбординг в дашборде и статические списки имён. Подробности по
каждому шагу — в журнале проходов ниже.

Перечисление `Platform` сведено с 23 членов к семи: `LOCAL`, `TELEGRAM`, `DISCORD`, `API_SERVER`,
`WEBHOOK`, `MATRIX`, `RELAY`. `DISCORD` и `MATRIX` оставлены сознательно: за ними живые ветки
фич (голос Discord, авто-треды, resume по комнатам Matrix, идентичность relay) — их снятие
это удаление фич, а не чистка имён.

## Состояние CI — НЕ РАБОТАЕТ (нерешённое)

**Симптом.** Любой прогон воркфлоу `CI` создаётся и навсегда остаётся `pending` с **нулём джоб**
(`gh api …/runs/<id>/jobs` → `total_count: 0`), а `gh run rerun` отвечает
`its workflow file may be broken`. Следующий пуш помечает такой прогон `cancelled`.
То же у `Nix flake check`. При этом `Docker Build, Test, and Publish` и `Deploy Site` проходят
за 17–20 секунд на тех же коммитах.

**Что проверено и исключено:**
- YAML всех воркфлоу валиден (PyYAML + строгая проверка дублей ключей — дублей нет);
- все локальные `uses:` существуют, у всех 24 вызываемых воркфлоу объявлен `workflow_call`;
- ключи джоб/шагов соответствуют схеме GitHub, `needs`/`outputs`/входы/секреты сходятся
  (статическая проверка — 0 проблем);
- `actionlint` 1.7.7 — ошибок в `ci.yaml` и `nix.yml` нет;
- минимальный воркфлоу `on: push` → **проходит** (`znth smoke`);
- джоба `detect` из `ci.yaml`, вынесенная в отдельный файл, → **проходит**;
- зависших `in_progress` прогонов, держащих группу concurrency, нет;
- ветка не защищена, окружений с approval нет, Actions включены, все воркфлоу `active`.

**Что сделано попутно (оставлено):** из блоков `concurrency` пуш-триггерных воркфлоу убрано
сравнение с `inputs.release` (контекста `inputs` на push-событии нет; `docker.yml`, который
сравнивает строковый `inputs.release-phase`, работает). Семантика сохранена: PR сворачивается по
номеру, релизный прогон владеет своим `run_id`, push использует `ref`. Симптом это не сняло.

**Дальше:** бисекция по остальным 26 джобам `ci.yaml` (полная копия файла тоже не поднимается,
а `detect` в одиночку проходит — значит, виновата одна из остальных джоб). Проверять по одной,
заменяя `uses:` на пустышку с теми же входами, чтобы не запускать тяжёлые пайплайны.

## Тесты

Удалены 185 файлов, которые **физически не собирались** (импортировали снятый модуль или член
перечисления) — список взят из вывода `pytest --collect-only`, не по догадкам. После чистки
сбор идёт без ошибок: `tests/gateway` — 7 387 тестов, `tests/plugins` + `tests/hermes_cli` —
17 202.

**Открытый хвост.** Прогон `tests/gateway` до первых 25 падений: все падения — в
`tests/gateway/relay/` (`relay_slack_dm_streaming`, `relay_inbound_dedupe`, `relay_explicit_disable`,
`relay_adapter`, `relay_interactive`), 63 упоминания Slack в выводе. Это следствие правок
relay-слоя при срезе Slack-веток. Решение не принято: либо эти тесты — про снятый Slack-лейн
(тогда удаляются тем же правилом), либо часть из них сторожит общую семантику relay, и тогда
чинить надо код. Разбирать поштучно, не наугад.

## Поправка к истории коммитов

Сообщение коммита `981a1b45` обещает, что «CI и Nix снова запускаются». Это неверно: правка
`concurrency` симптом не сняла — прогоны по-прежнему создаются без джоб. Правка остаётся
полезной (контекста `inputs` на push нет, `actionlint` чист), но запуск CI она не чинит.
